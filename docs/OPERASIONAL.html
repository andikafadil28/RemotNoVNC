REMOTE RS

Panduan Operasional

Dashboard remote desktop berbasis React, Fastify, noVNC, TightVNC, Caddy, dan Docker Compose.

Versi 1.0
Dokumen untuk tim IT internal.

1. Tujuan dan Arsitektur

Remote RS menyediakan dashboard web untuk memantau dan mengendalikan komputer Windows yang sudah menjalankan TightVNC Server. Endpoint tidak memerlukan agent baru.

Browser IT LAN/VPN
  - HTTPS/WSS TCP 8443
  - Caddy + dashboard React
  - Fastify WebSocket gateway
  - TightVNC endpoint TCP 5900

Stack Docker hanya mempublikasikan TCP 8443. API TCP 3000 hanya tersedia di network Docker internal sehingga tidak mengganggu aplikasi host lain.

2. Batasan POC

  • Inventory, user, dan audit disimpan sebagai JSON pada volume remote-rs_remote-rs-data.
  • Maksimal 16 koneksi VNC aktif per halaman, dengan pilihan 2 sampai 5 kolom.
  • Grid normal view-only. Kontrol aktif hanya saat fullscreen.
  • Password VNC dimasukkan manual dan hanya berada di memori browser selama sesi.
  • File transfer, terminal, monitoring resource, dan alert belum tersedia.
  • Sebelum rollout besar, migrasikan data ke PostgreSQL dan lakukan load test.

3. Prasyarat

  • Ubuntu, Docker Engine, Docker Compose, dan Git.
  • TCP 8443 kosong pada server.
  • Server dapat mengakses endpoint TightVNC pada TCP 5900.
  • Client IT dapat mengakses TCP 8443 melalui LAN atau VPN.
docker --version
docker compose version
sudo ss -ltnp 'sport = :8443'

4. Instalasi

git clone https://github.com/andikafadil28/RemotNoVNC.git ~/remote-rs
cd ~/remote-rs
cp deploy/.env.example deploy/.env
chmod 600 deploy/.env
nano deploy/.env

Isi REMOTE_RS_HOST, ADMIN_USERNAME, dan ADMIN_PASSWORD. Gunakan password unik minimal 10 karakter.

Jangan commit, screenshot, atau kirim isi deploy/.env melalui chat.
docker compose -f deploy/compose.yaml up -d --build
docker compose -f deploy/compose.yaml ps

Status service api dan web harus Up.

5. Firewall dan HTTPS

Buka TCP 8443 hanya untuk subnet admin yang disetujui:

sudo ufw allow from <subnet-admin>/24 to any port 8443 proto tcp
sudo ufw status verbose

Export root certificate Caddy:

cd ~/remote-rs
docker cp remote-rs-web-1:/data/caddy/pki/authorities/local/root.crt ./remote-rs-root.crt
chmod 600 remote-rs-root.crt

Import pada Windows Current User ke Trusted Root Certification Authorities:

certutil -user -addstore Root "$env:USERPROFILE\Downloads\remote-rs-root.crt"
Jangan gunakan HTTP. Dashboard membawa kredensial, layar desktop, keyboard, mouse, clipboard, dan kemungkinan data pasien.

6. Hak Akses

Admin: scan VNC, CRUD endpoint, buat akun, dan lihat audit.

Teknisi: lihat status dan membuka remote desktop.

Gunakan akun personal. Hindari akun bersama untuk penggunaan production.

7. Inventory dan Remote

  1. Scan subnet atau tambah endpoint manual.
  2. Isi nama PC, group, lokasi, dan IP privat.
  3. Pilih group dan masukkan password VNC pada tile.
  4. Gunakan grid untuk pantau.
  5. Klik Fullscreen untuk kontrol mouse dan keyboard.
  6. Tekan Esc untuk kembali ke mode pantau.
  7. Klik Reconnect jika sesi terputus.

Token remote sekali pakai, terikat session user, dan kedaluwarsa dalam waktu singkat.

8. Operasi Harian

cd ~/remote-rs
docker compose -f deploy/compose.yaml ps
docker compose -f deploy/compose.yaml logs --tail=100
docker compose -f deploy/compose.yaml restart

Container memakai restart: unless-stopped. Container otomatis aktif setelah reboot kecuali sebelumnya dihentikan manual.

sudo systemctl enable --now docker
systemctl is-enabled docker

9. Update

Lakukan backup sebelum update.

cd ~/remote-rs
git pull --ff-only
docker compose -f deploy/compose.yaml up -d --build
docker compose -f deploy/compose.yaml ps

Setelah update, verifikasi login, status, remote desktop, fullscreen, reconnect, dan audit.

10. Backup

mkdir -p ~/remote-rs-backup
docker run --rm \
  -v remote-rs_remote-rs-data:/data:ro \
  -v ~/remote-rs-backup:/backup \
  alpine sh -c 'tar czf /backup/remote-rs-data-$(date +%Y%m%d-%H%M%S).tar.gz -C /data .'

cp ~/remote-rs/deploy/.env ~/remote-rs-backup/deploy.env.backup
chmod 600 ~/remote-rs-backup/deploy.env.backup

Simpan backup terenkripsi di lokasi terpisah dan uji restore berkala.

11. Restore

Peringatan: restore mengganti data aktif. Pastikan file backup benar dan stack API dihentikan.
cd ~/remote-rs
docker compose -f deploy/compose.yaml stop api
docker run --rm \
  -v remote-rs_remote-rs-data:/data \
  -v ~/remote-rs-backup:/backup \
  alpine sh -c 'rm -rf /data/* && tar xzf /backup/<nama-backup>.tar.gz -C /data'
docker compose -f deploy/compose.yaml start api

12. Troubleshooting

Dashboard tidak dapat dibuka

docker compose -f deploy/compose.yaml ps
sudo ss -ltnp 'sport = :8443'
sudo ufw status verbose
docker compose -f deploy/compose.yaml logs --tail=100 web

Login gagal

docker compose -f deploy/compose.yaml logs --tail=100 api
docker compose -f deploy/compose.yaml exec web wget -S -O- http://api:3000/api/auth/session

Respons 401 Unauthorized berarti API hidup dan meminta login.

Status Unknown atau remote terputus

  • Cek container API dan endpoint TCP 5900.
  • Pastikan firewall endpoint mengizinkan IP server dashboard.
  • Klik Reconnect dan lihat audit terakhir.
  • remote.failed: gagal membentuk koneksi.
  • remote.closed.client: browser menutup sesi.
  • remote.closed.endpoint: endpoint atau jaringan menutup sesi.

Container web Restarting

docker compose -f deploy/compose.yaml logs --tail=100 web

Periksa syntax Caddy dan nilai REMOTE_RS_HOST, lalu rebuild.

13. Security Checklist

  • Akun personal dan password unik.
  • TCP 8443 hanya untuk LAN admin atau VPN.
  • TCP 5900 endpoint hanya dari server dashboard.
  • Jangan publish .env, inventory, audit, atau data user.
  • Jangan abaikan warning certificate.
  • Review audit dan backup rutin.
  • Gunakan MFA dan PostgreSQL sebelum rollout luas.
  • Hindari screenshot data pasien pada kanal publik.

14. Data Insiden

Catat waktu kejadian, username teknisi, endpoint target, action audit terakhir, status container, dan log relevan. Jangan sertakan password atau data pasien.
